# 文档结构规范

## 目标
- 让需求、设计、技术、交付全过程可追溯
- 让新成员能够在 30 分钟内理解项目主干
- 保持可扩展性，避免文档碎片化

## 目录层级建议

- `00-` 纲领与目录
- `10-` 产品与业务
- `20-` 技术与架构
- `30-` 研发流程与交付
- `40-` 运营与市场

## 编写规范

- 文件名采用 `编号-标题.md` 格式
- 在顶部提供“目的 / 范围 / 关键结论”三段式摘要
- 重要决策在文末记录“决策日志”
- 单文档单职责：一个文件只承载一个主主题
- 单文档默认行数上限 220，超限必须拆分为子文档并互相链接
- 技术文档必须包含“边界说明”：明确不做什么、交给哪个文档负责
