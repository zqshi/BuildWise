# 统一持续建模重建基线

## 目的

定义 BuildWise 从“展示型项目建模”升级到“统一持续建模平台”的领域基线，作为后续架构、实现、测试与 OpenClaw skill 编排的共同约束。

## 范围

In scope:

- 项目级统一模型内核
- 迭代继承与模型快照
- 业务术语本体与技术术语映射
- 业务规则、实体关系、能力视图、接口契约、追溯链
- 业务确认任务与模型发布流程

Out of scope:

- 旧 `v2/model.json` 继续扩展
- 在现有项目总览页上继续叠加展示逻辑
- 直接把 OpenClaw chat 结果当作正式模型资产

## 核心问题定义

现状存在三套彼此割裂的资产来源：

1. `v2/model.json` 中的静态实体、关系、规则、页面、接口。
2. 项目 `knowledgeBase` 中的术语、稳定规则、组件与代码映射。
3. 迭代 `changeControl` 中的追溯快照、领域知识、边界与质量产物。

问题不在“缺少信息”，而在“没有统一聚合根”。因此系统无法稳定回答：

- 当前项目的正式业务模型是什么。
- 本轮迭代相对上一轮改动了什么。
- 业务术语和技术术语如何稳定映射。
- 哪些变更已经被业务确认，哪些仍待确认。
- 关系图、摘要、影响分析、质量门禁是否引用同一事实源。

## 目标状态

BuildWise 重建后应以 `ProjectModel` 为核心聚合，围绕 `ModelSnapshot` 组织所有派生能力。

### 核心聚合

- `ProjectModel`
- `ModelSnapshot`
- `OntologyTerm`
- `BusinessEntity`
- `BusinessRelation`
- `BusinessRule`
- `BusinessCapability`
- `ViewModel`
- `ApiContract`
- `TraceLink`
- `ReviewTask`
- `ModelEvidence`

### 关键约束

- 每个项目必须存在唯一当前正式模型快照。
- 每个迭代都必须从基线快照继承并生成候选快照。
- 业务术语、本体、别名、技术术语映射必须版本化。
- 任何确认后的业务规则都必须落到工程对象或待办确认项上。
- 关系图、摘要、影响分析、门禁与审计必须从同一快照派生。

## 领域上下文

### `continuous-modeling`

职责：

- 管理模型快照与版本差异
- 管理快照发布、废弃与继承
- 输出供其他上下文消费的统一模型视图

### `ontology-language`

职责：

- 管理业务术语、本体定义、别名与技术映射
- 管理术语冲突、合并与确认状态

### `change-traceability`

职责：

- 将需求、模型、页面、接口、代码、测试连接为可追溯链路

### `delivery-governance`

职责：

- 基于模型变更驱动测试矩阵、发布门禁与回滚依据

### `workspace-interaction`

职责：

- 为业务人员提供确认入口、差异视图、任务列表与说明界面

## 统一模型生命周期

1. `ingest`
   收集需求文本、附件、知识库、迭代上下文、仓库元数据。
2. `extract`
   抽取术语、业务对象、规则、能力、页面意图、接口意图。
3. `normalize`
   将业务与技术术语映射到本体层。
4. `reconcile`
   与上一版快照比对，生成候选增量。
5. `review`
   生成待业务确认项，阻止未确认高风险变更直接发布。
6. `publish`
   发布新的正式模型快照。
7. `drive`
   让摘要、图谱、影响分析、门禁、追溯都消费该快照。

## 风险与缓解

风险等级：高。

风险点：

- 旧模型仓、项目知识库、迭代分析结果并存，容易继续双轨运行。
- 如果 OpenClaw 先扩展、模型内核后补，会形成新的“会话真相”。
- 如果业务确认链没有进入平台，业务仍会依赖研发理解技术术语。

缓解：

- 冻结旧 `modeling` 上下文新增需求，只允许缺陷修复。
- 新能力全部落入 `continuous-modeling` 和 `ontology-language`。
- 所有 skill 输出必须写回正式模型或待确认任务，而不是只生成文本。

## 验收标准

- 任意项目可查看当前正式模型快照与上一版差异。
- 任意业务术语可查看标准定义、别名、技术映射和证据。
- 任意业务规则可追溯到页面、接口、状态、测试或未确认任务。
- 项目摘要、图谱、影响分析与发布门禁读取同一快照。
- OpenClaw 编排输入不再直接拼接零散上下文，而是消费统一模型视图。
