# 工程执行标准（技术栈与模式）

## 技术栈标准

- 前端：`React + TypeScript + Vite`
- 后端：`Fastify + TypeScript`
- 存储：阶段内默认 `JSON Repository`，后续可切换 DB Adapter
- 自动化：`autoboot/pipeline.py`

## 设计模式标准

- 后端：DDD 分层 + Repository + Application Service
- 前端：Container/Presenter 分离（逐步推进）
- 禁止把领域规则直接写进 HTTP 路由和 UI 样式文件
- 默认采用“单系统叠加”交付模式：新能力叠加到统一工作台，不新增 `legacy/*.html` 页面文件

## 代码质量标准

- 所有新增功能必须有边界守卫通过：
  - `npm run check:boundaries`（前端）
  - `npm run check:boundaries`（后端）
- 所有提交前必须构建通过：
  - `npm run build`（前端）
  - `npm run build`（后端）
- 行数控制必须执行：
  - `v2/src/App.tsx`、`v2/src/styles/app.css`、`v2/src/pages/**`、`v2/backend/src/**`、`docs/**` 统一受守卫约束
  - 超过阈值必须拆分，不允许“临时放开阈值”替代重构

## 文档沉淀标准

- 每个里程碑必须沉淀：
  - 目标与范围
  - 验收结果
  - 风险与回滚记录
- 每个关键技术决策必须有 ADR（可追溯到版本与代码路径）。
- 文档边界必须清晰：
  - 单文档单主题
  - 单文档默认不超过 220 行
  - 跨主题内容必须拆分到新文档并在 `docs/README.md` 建立索引

## 自动执行上下文标准

- 每次 `plan/run/autoloop` 必须注入统一上下文：
  - 产品顶层设计
  - 技术架构设计
  - DDD 边界规范
  - 版本里程碑计划
  - 工程执行标准
