# 统一持续建模平台重建路线图

## 目标

分阶段将 BuildWise 从“项目总览里的建模展示”演进为“业务可自迭代的统一持续建模平台”。

## 阶段 1：重建基线

目标：

- 冻结旧建模扩展
- 建立领域蓝图、ADR、工程治理、OpenClaw 承接策略
- 建立 `continuous-modeling` 代码骨架与测试骨架

完成标准：

- 文档基线完成
- 首批领域对象与服务存在
- 首批测试通过

## 阶段 2：模型内核落地

目标：

- 引入项目模型快照
- 引入基线继承与候选快照
- 引入术语本体与别名映射

完成标准：

- 项目可生成正式与候选快照
- 迭代可查看快照差异
- 术语可映射到工程对象

## 阶段 3：OpenClaw 执行承接

目标：

- skill 输入切换到统一模型视图
- 新增快照协调与结构化实体构建技能
- 生成业务确认任务并回写
- 建立原型驱动的 `prototype -> architecture -> code -> test` 执行 loop

完成标准：

- orchestrator 能基于快照推进迭代
- skill 输出可写回模型候选更新
- 开发与测试阶段不再一次性“生成代码后结束”，而是持续循环到达到可投产交付门槛
- `productionDeliveryLoop.state` 能在真实迭代上推进到 `ready_for_release`，且非 ready 状态会阻断发布评审与远端发布

## 阶段 4：派生能力迁移

目标：

- 关系图、摘要、影响分析、发布门禁、追溯都改为消费正式快照

完成标准：

- 页面不再直接拼散落数据
- 同一变更在所有视图中结果一致

## 阶段 5：旧链路退役

目标：

- 旧 `model.json` 退出正式模型职责
- 清理重复文档、脚本与过时数据结构

完成标准：

- 文档与代码中不存在新的旧链路引用
- 仓库内模型事实源唯一
