# 47-DDD+TDD 与 1000 行治理最高声明

## 目的

将 BuildWise 的研发方式统一为可执行、可检查、可回归的工程治理机制，避免架构退化、逻辑冗余和文档滞后。

## 最高原则（强制）

1. DDD + TDD
- 领域模型、应用服务、接口层与基础设施层边界必须明确。
- 任何行为变更必须配套自动化测试（至少契约测试或对应层测试）。
- 禁止“先上线后补测”作为常态流程。

2. 单文件 1000 行硬上限
- 代码、脚本、文档都受 1000 行硬上限约束。
- 存量超限文件仅允许在白名单中临时存在，并需要持续拆分治理。
- 新增超限文件一律禁止。

3. 职责单一与非冗余
- 每个文件只承担一个清晰职责，避免“万能文件”。
- 禁止重复定义规则、重复脚本、重复文档表述。
- 引入新文件前必须先确认无等价资产可复用。

4. 变更系统性分析
- 变更前必须明确 In scope / Out of scope。
- 必须识别对模块、API、数据、配置、部署、测试的影响。
- 变更后必须执行质量门禁并记录结果。

5. 文档与实现同步更新
- 功能、接口、流程变更必须同步更新相关文档和校验脚本。
- 不允许出现“代码已变更但文档/门禁滞后”的状态。

6. Agent+Skills Prompt 最小化原则
- 固定采用 `Agent + Skills` 单编排 Agent，避免无必要的多角色 Prompt 扩散。
- Prompt 仍必须保留：它是结构化输出契约与质量门禁载体，不等价于“角色数量”。
- 允许角色收敛，但不允许取消输出契约、边界约束、校验规则。

## 执行机制

1. 自动化门禁
- `v2/scripts/check-boundaries.mjs` 执行 DDD 边界检查与行数限制检查。
- `v2/scripts/boundary-exceptions.json` 管理存量例外（含 1000 行硬上限例外）。
- `v2/scripts/check-repo-hygiene.mjs` 执行仓库卫生检查。

2. 标准验证链
- 前端：`npm run check:hygiene && npm run check:boundaries && npm run typecheck && npm run build`
- 后端：`npm run check:boundaries && npm run typecheck && npm run build && npm run test:contract`

3. 存量治理要求
- 每次迭代至少减少一个超限文件规模或拆分一个超大职责块。
- 若无法当次完成拆分，必须在变更说明中给出下一步拆分计划和风险控制。
