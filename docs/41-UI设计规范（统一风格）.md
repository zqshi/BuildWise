# UI 设计规范（统一风格）

## 目标

- 建立单一视觉语言，降低页面风格漂移。
- 保证“可读、可操作、可反馈”的交互体验。
- 让前端实现与设计决策可追溯、可复用。

## 设计令牌（Design Tokens）

- 统一定义位置：`v2/src/styles/app.css` 的 `:root`
- 字体：
  - `--font-sans`: `"PingFang SC", "Noto Sans SC", "Microsoft YaHei", sans-serif`
- 字号：
  - `--text-xs`: 12px
  - `--text-sm`: 13px
  - `--text-md`: 14px
  - `--text-lg`: 18px
  - `--text-xl`: 22px
  - `--text-2xl`: 24px
- 颜色：
  - 文本：`--text-primary` / `--text-secondary` / `--text-muted`
  - 品牌：`--brand-500` / `--brand-600` / `--brand-100` / `--brand-50`
  - 语义：`--danger-500` / `--danger-50`
  - 背景：`--bg-canvas` / `--bg-surface` / `--bg-surface-muted` / `--bg-control`
  - 边框：`--border-default` / `--border-strong` / `--border-brand`
- 圆角：
  - `--radius-sm`(8) / `--radius-md`(10) / `--radius-lg`(12) / `--radius-xl`(14)
- 阴影：
  - 卡片：`--shadow-card`
  - 浮层：`--shadow-float`

## 组件规范

- 按钮（`.btn`）：
  - 主按钮：`.btn.primary`，品牌渐变背景 + 提升阴影。
  - 次按钮：`.btn.ghost`，中性背景，hover 加深。
  - 禁用状态：统一降透明，禁止位移动画。
- 输入框：
  - 默认边框 `--border-strong`，focus 使用品牌高亮环。
  - 错误状态 class `error` 使用 `--danger-500`。
- 卡片/面板：
  - 统一 `background: --bg-surface`
  - 统一 `border: --border-default`
  - 圆角优先 `--radius-md` / `--radius-lg`
- 列表项（项目/迭代）：
  - hover 与 active 均使用品牌浅色背景，不引入额外色系。

## 交互反馈规范

- 登录校验：
  - 禁止弹窗打断（不使用 `alert`）。
  - 采用“失焦提示 + 提交后统一提示”。
  - 首次提交失败自动聚焦第一个错误字段。
- 菜单与浮层：
  - 点击外部关闭。
  - 按 `Esc` 关闭（键盘友好）。
- 可访问性：
  - 错误字段必须有 `aria-invalid` 和 `aria-describedby`。
  - 可交互元素必须有可见 focus 样式（`:focus-visible`）。

## 实施约束

- 新页面/新组件禁止直接写硬编码色值，必须优先复用 token。
- 新增样式前先判断是否可复用现有 `.btn/.panel/.info-box/.hint` 等基础类。
- 样式改动需至少通过：
  - `npm run typecheck`
  - `npm run build`

## 后续建议

- 分离 `app.css` 为 `tokens.css + components.css + pages.css`，降低单文件复杂度。
- 在 PR 检查中加入“硬编码颜色扫描”规则，阻止规范回退。
