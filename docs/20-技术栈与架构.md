# 技术栈与架构

## 目的
统一技术选型，为未来 3-5 年扩展性与维护性建立基线。

## 栈选择（当前建议）

### 前端
- **Vite + React + TypeScript**
- 理由：
  - 快速开发与构建，生态成熟
  - TS 提升可维护性与协作效率
  - 适合未来演进为复杂建模工作台

### 后端
- **Node.js + Fastify + TypeScript**
- 理由：
  - 高并发与低资源占用
  - 与前端共享 TS 生态与工具链
  - 便于构建多服务与模块化系统

### 数据与存储
- **SQLite（本地演示） → Postgres（生产）**
- **对象存储**（模型快照、设计稿、草图）

### 基础设施（阶段性）
- MVP 期：本地 + Docker
- 规模化：K8s + CI/CD + 观察性

## 架构分层

- 输入与交互层：多源输入、流程模式与智能体模式
- 核心引擎层：统一项目模型、规则编译器、同步引擎
- 输出平台层：多栈生成器、部署与运维、开放 API
- 支撑服务层：知识库、模型服务、任务编排

## 决策日志
- 2026-02-09：确定 Vite + React + TS 与 Fastify + TS 作为初始栈
