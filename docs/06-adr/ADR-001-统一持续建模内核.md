# ADR-001 统一持续建模内核

## 状态

Accepted

## 日期

2026-03-17

## 背景

BuildWise 当前的建模资产分散在静态模型仓、项目知识库和迭代变更分析结果中。系统可以展示关系和生成摘要，但无法形成稳定的项目级模型真相，也无法支撑业务侧持续自迭代。

## 决策

引入统一持续建模内核，以项目级 `ModelSnapshot` 作为单一事实源。

### 关键决策点

- 旧 `v2/model.json` 不再承接新正式模型能力。
- 新能力围绕 `continuous-modeling` 上下文建设。
- OpenClaw 作为编排与治理层，不作为正式模型存储层。
- 业务术语与技术术语映射通过本体层版本化管理。

## 影响

正向影响：

- 项目可持续继承与差异化演进
- 业务术语可稳定映射工程实现
- OpenClaw 编排具备统一事实源

代价：

- 需要新增领域对象、应用服务、迁移脚本和测试体系
- 旧展示链路需要逐步迁移

## 替代方案

### 继续扩展 `v2/model.json`

拒绝原因：

- 无法表达项目级与迭代级快照
- 无法解决知识库、迭代分析和静态模型分裂问题

### 直接用 OpenClaw 对话结果当模型真相

拒绝原因：

- 对话结果不具备稳定领域边界
- 难以版本化、验证和审计

## 后续动作

- 建立 `continuous-modeling` 领域骨架与测试
- 升级 OpenClaw skill 链
- 逐步迁移图谱、摘要、影响分析和门禁
