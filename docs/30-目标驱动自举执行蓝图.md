# 目标驱动自举执行蓝图（主执行口径）

## 1. 北极星目标（唯一）

将**非技术创造者的业务意图**，以可控、低损耗、可持续迭代的方式，编译为**可维护、可演进的软件资产**。

判定标准（目标层）：
- 业务意图到可运行系统的首轮交付周期显著缩短（周/月 -> 天/小时）
- 需求变更后可稳定同步，不依赖人工全量返工
- 产出是可维护资产（而非一次性黑盒）

## 2. 自举循环的角色定位

自举循环是**执行机制**，不是目标本身。

- 目标负责“做什么”
- 自举循环负责“如何稳定做到”

统一循环：`Goal -> Plan -> Apply -> Verify -> Report -> Next`

## 3. 阶段拆解（目标导向）

### 阶段 S1：最小可用编译闭环（当前必须完成）
目标：证明“意图 -> 模型 -> 代码/界面”闭环成立。

任务包：
- 统一项目模型最小结构稳定（实体/字段/规则/页面）
- 模型中台可见（规则编译、同步评分、追溯预览）
- 项目/迭代/评估/快照主链路可运行
- 核心契约测试覆盖成功与失败路径

退出条件：
- 前后端 `build/typecheck/boundaries/contract` 全绿
- `autoboot pipeline verify` 全绿
- 前端存在可见业务能力，不是纯占位

### 阶段 S2：稳定同步与低损耗变更
目标：需求变更可精准影响分析与增量同步。

任务包：
- 规则编译与绑定升级为可解释结果（含失败原因）
- 同步报告引入“影响范围+风险项”
- 追溯链路支持模型节点到代码定位
- 变更回归测试（快照回放）

退出条件：
- 同步场景失败可回滚
- 关键链路有自动化回归样例集

### 阶段 S3：复杂业务可表达
目标：支持真实业务复杂度而非仅 CRUD。

任务包：
- 关系建模（1:N / N:N）
- 状态机与流程规则
- 权限与治理基础
- 多角色协作最小闭环

退出条件：
- 至少 1 个真实业务场景全流程跑通
- 复杂规则改动不破坏基础闭环

### 阶段 S4：产品化与投产运营
目标：从工程可用变成产品可运营。

任务包：
- 发布/部署/可观测最小体系
- 运行手册、故障恢复、回滚演练
- 指标体系（交付时效、失败率、修复时长）
- 版本节奏与里程碑制度化

退出条件：
- 可重复部署、可重复验收、可重复回滚

## 4. 每阶段任务拆解模板

每次自循环任务必须按以下 6 项生成：

1. 目标：本轮只对齐一个阶段子目标
2. 变更：前端/后端/模型/文档具体改动
3. 验证：命令级门禁列表（必须可执行）
4. 风险：本轮引入或暴露的风险
5. 回滚：失败时回滚路径与触发条件
6. 报告：阶段产物路径（PRD/TECH/Review）

## 5. 非目标清单（执行约束）

以下内容在 S1-S2 期间默认禁止：
- 平台生态化功能（模板商店、开放市场、企业经营分析）
- 与核心闭环无关的页面扩张
- 无验收价值的接口堆叠与占位实体堆叠
- 大规模技术重构且无直接目标收益

## 6. 当前阶段判定（截至本次）

依据：

下一轮只允许进入 S2 任务池，不得回到无目标扩张。

## 7. 自循环执行指令（标准）

每轮执行前：
- 读取本文件 + 10/20/40 执行版文档 + context manifest

每轮执行后：
- 产出 `docs/milestones/review-*.md`
- 更新 `autoboot/state.json` 中 `latest_milestone_review`
- 若未达到阶段退出条件：继续下一轮；达到则阶段自动停止并切换下一阶段任务池
