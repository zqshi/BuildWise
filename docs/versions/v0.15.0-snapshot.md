# v0.15.0 Snapshot — 体检待修修复

> 状态: 已归档 snapshot（2026-06-26，verify:all 全绿，代码 6 批分层入库）
> 起始 commit: 42aef6a (2026-06-26，v0.14.0 归档激活)

## 版本目标

6/26 质量体检发现 7 项代码层待修点。本版本修复其中 4 项（P1×2 + P2×2）：merge-rewrite 空转死代码、fullCycle 缺中断/取消能力、autoResolve 旁路澄清门禁、lint 长期漏网。诊断第 5/6/7 项（policyGate 治理盲区 / changeControl 与 fullCycle checkpoint 双状态解耦 / FullCycle Job 重启恢复对齐 Analysis Job + changeImpact 集成）遗留 v0.16.0。

核实证据时修正诊断两处事实错误：① autoResolve 是前端 `chatActionFullCycle.ts:82/103` 硬编码 `true` + 后端 `!== false` 双保险旁路门禁（非诊断所述"后端默认旁路"），且 confirmation 步骤早有 blocked 分支只是被旁路；② lint 漏报了后端 36 error（诊断只提前端 7 error），但 biome.json 早已将 noNonNullAssertion/noImplicitAnyLet/useExhaustiveDependencies 降为 warn，实际 error 级问题远少于诊断所述。

## 版本验证标准

1. fullCycle 改写结果不再空转：前端展示与 delivery/publish 拿到的改写汇总含实际改写文件
2. fullCycle 运行中可取消：用户触发后后端于步骤边界停止，checkpoint 保留可续跑，不跑完整 30min+ LLM 链
3. fullCycle 遇未收敛澄清问题默认阻断（守门禁），仅显式 `autoResolveClarifications=true` 才放行
4. verify:all 真绿（含新增 lint 门槛）

## 关键技术决策表

| 决策 | 理由 |
|------|------|
| T2 取消采用步骤边界检查而非 AbortController 全链路穿透 | AbortController 子进程/LLM 调用难透传；步骤边界检查在已完成步骤跑完后停止，不粗暴 abort 当前 LLM 调用，与 v0.14.0 checkpoint 续跑范式契合；远好于跑完 30min 全链 |
| T2 取消复用 codeRewriteJobOps 的 cancelled 状态机范式 | codeRewriteJobOps 早有 `"cancelled"` 状态，fullCycle Job 状态机对齐同语义 |
| T2b 停止按钮 UI 遗留 v0.16.0 | 取消能力核心已闭环（API 可调 + 轮询正确终止 + catch 展示），停止按钮是 UX 入口完善，需 ChatContext→ProjectsWorkspace→ChatComposer 多层 props drilling 改造暴露 jobId，建议与前端 UI 重构合并避免重复 |
| T3 默认守门禁而非暴露前端开关 | 用户拍板默认守门禁，符合 CLAUDE.md「未收敛澄清问题应阻断确认」规格；confirmation 已有 blocked 分支无需新逻辑 |
| T4a 不改 biome.json 降级规则 | biome.json 早已合理降级 warn（noNonNullAssertion 等在 TS 项目误报率高），问题在 verify 链路漏 lint 而非规则设置；清实际 error + 纳入 verify 即可 |
| 诊断证据逐条核实而非照搬 | 核实时修正两处事实错误（autoResolve 来源 / lint 漏报后端），避免按错误诊断改错地方 |

- **T2b fullCycle 停止按钮 UI 入口**（P2）：取消能力核心已完成，缺前端可见的停止按钮。需 ChatContext/ChatActionDeps/runFullCycleWithPolling 暴露 jobId 经新停止按钮组件 + ProjectsWorkspace 多层 props drilling 改造。转入 v0.16.0，建议与前端 UI 重构合并。

- **per-prefix 行数软警告**：跨版本技术债务，check-boundaries non-blocking（fullCycleOps 505 / normalizeHelpers 620 等，均未触 800 硬限）。
- **前端 useExhaustiveDependencies/noNonNullAssertion 等 warning**：biome.json 降级 warn 不阻断，React hook deps 误报为主，后续逐个评估。
