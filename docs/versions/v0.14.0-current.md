## 版本目标

v0.13.0 完成需求池归属交互 + 三道门禁加固，verify:all 真绿。本版本聚焦 v0.13.0 流畅性审查暴露的**架构级流畅性短板**（非局部 bug）：

- **fullCycle 全管道同步阻塞单 HTTP**（流畅性最大短板）：一次 fullCycle 含分析+确认+UX+前后端改写+测试+评审+发布，5-6 次 LLM + agent 执行，可能 30min+，任何网关超时（nginx 默认 60s）即断连，前端拿到断连错误而非管道状态。
- **分析 Job 内存态**：进程重启后 running 任务变"幽灵 running"无 worker，前端轮询永远等不到。

v0.8.0 已落地 `codeRewriteJobOps` 异步 Job 状态机（pending→running→completed/failed/timeout）+ 前端轮询退避，本版本复用该模式改造 fullCycle。

## 版本验证标准

1. fullCycle 触发后立即返回 jobId，HTTP 不阻塞；前端轮询拿管道进度与最终结果
2. 进程重启后，重启前 running 的 fullCycle/分析 Job 能被识别并恢复或标记失败，不卡死
3. fullCycle 步骤失败时已写盘文件回滚，不产生"半改写"状态（不造假）
4. verify:all 真绿（含子进程契约 + in-process 契约 + prompt 动态扫描）
