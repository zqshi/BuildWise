# v0.30.0 Current — 按端质量数据 + LLM 按端评审

> 状态: 进行中
> 起始 commit: 8f76c4d (2026-06-29)
> 上一版本: [v0.29.0](v0.29.0-snapshot.md)

## 版本目标

v0.29.0 引入「目标端」维度并堵死虚假 go（门禁端级聚合），但 LLM 按端评审（T3）因缺按端真实质量数据转后续。本版本补齐按端质量数据（测试矩阵按端分组 + 代码路径按端白名单），让 LLM 按端评审有真实依据，`releaseReview.perPlatform` 数据流入前端按端展示（v0.29.0 T6.7 UI 已就绪待数据）。

## 版本验证标准

1. 测试矩阵 generatedTestMatrix 按声明端分组，每端有 coverage/passRate；
2. 代码路径 codePathWhitelist/boundaryCodePaths 按端白名单，agent 改动按端归属校验；
3. releaseReview LLM 按端评审产出 perPlatform（每端 decision/blockers 有按端数据依据），前端按端展示生效（不再降级整体展示）。

## 版本范围

**做什么:**
- 测试矩阵 generatedTestMatrix 按端分组（coverage/passRate per platform）
- 代码路径 codePathWhitelist/boundaryCodePaths 按端白名单
- T3（v0.29.0 转入）：synthesizeReleaseReviewOp 按 targetPlatforms 对每端出 decision/blockers + domain releaseReview 产出 perPlatform + 解析/校验链
- 前端按端展示数据接入（v0.29.0 T6.7 UI 已就绪，perPlatform 数据流入即生效）

**不做什么:**
- 各端 CI/构建链接入（超出 BuildWise 边界）→ 按需

### T2 — 代码路径按端白名单（done，已分层入库）
**核心判断**：T2 是端级门禁「统计层」非越界「阻断层」。`assertBoundaryWhitelist`（boundaryGuard.ts，越界阻断，agent 改写回滚+发布越界校验依赖）**不改**；"改 web 路径不视为 ios 完成"是端级完成度统计。证据：v0.29.0 `assessPlatformDeliveryReadiness` 注释"单端质量信号按端分组留 v0.30.0"，T2 补此预留位。与 T1 对称（T1 测试用例标端→按端聚合；T2 代码路径标端→按端统计改动）。

**数据结构**（平行字段，最小侵入）：`IterationChangeBoundary` 加 `codePathsByPlatform?: Record<TargetPlatform, string[]>`；保留 `codePaths: string[]` 不变 → 20+ 读写点 + assertBoundaryWhitelist + resolveBoundaryFileCandidates 零改动，旧数据降级不分端。

**路径归属端来源**（已拍板）：boundary-guardian agent LLM 标注每条 codePath 的 targetPlatform（仿 T1 synthesizeTestMatrixOp）+ 用户 boundary 编辑可修正。

**新增纯函数**（仿 T1 testMatrixSummaryOps）：`codePathByPlatformOps.ts` → `summarizeCodeChangesByPlatform(changedPaths, codePathsByPlatform, targetPlatforms)` 每端 `{total, changed, untouched}`；纯函数 + TDD。

**端级门禁接入**：新增 `assessPlatformCodeChangeReadiness`（独立纯函数，组合进 checkIterationPublishGates，不膨胀 assessPlatformDeliveryReadiness 交付物维度职责）：某端 codePathsByPlatform 有路径但 0 改动 → 该端 block。

**不改**：assertBoundaryWhitelist / resolveBoundaryFileCandidates / agent 改写流程 / executableConstraints.codePathWhitelist 平铺字段。

**步骤**：①domain 加字段（前后端同步）→ ②纯函数+测试 → ③端级门禁+测试 → ④LLM 标注（boundary-guardian prompt+解析+analysisOps 接入）→ ⑤normalize 兜底 → ⑥前端展示（后端先行，数据流入即接）。

**完成记录**：①②③④⑤done，⑥后置。
- ①domain `IterationChangeBoundary` 加 `codePathsByPlatform?: Record<TargetPlatform,string[]>`（前后端同步），保留 `codePaths` 平铺不变 → 20+ 读写点零改动。
- ②`codePathByPlatformOps.ts` → `summarizeCodeChangesByPlatform`（按端统计 ruleCount/changedFileCount/hasChange，路径前缀匹配去末尾斜杠 bug 修复，纯函数+7 测试含数据损坏边界）。

## 对后续版本的约束

- 按端质量数据（测试矩阵/代码路径）为 T3 LLM 按端评审的必要前置，不得在数据未齐备时让 LLM 编造按端结论（v0.29.0 T3 转后续的教训）；
- perPlatform 数据须有按端真实依据（测试覆盖/代码归属），非 LLM 推断；
- TargetPlatform 固定枚举不变，新增端加枚举值。
