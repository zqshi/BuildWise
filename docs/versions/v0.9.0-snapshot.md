# v0.9.0 Snapshot — V3 门禁 policyGate 硬阻断 + 统一后验层

> 状态: 已归档 snapshot（2026-06-25，verify:all 全绿）

## 版本目标

把 policyGate（policy 维度门禁：requiredArtifacts/requireHumanConfirmation）从软提示改为硬阻断阶段推进 + 交付物合成（不阻断 LLM 对话回复），新增统一后验层 postExecutionVerifier + 门禁绕过检测审计。原 policyGate 只进 LLM prompt 当提示不阻止推进，用户配置的策略门禁形同虚设。

## 交付内容摘要

| 文件 | 内容 |
|------|------|
| `coach/postExecutionVerifier.ts` | 统一后验纯函数：shouldBlockStageAdvance/shouldBlockArtifactSynthesis（stage+policy gate 任一阻断）+ sanitizeAction/sanitizeIntent（白名单降级）+ detectGateBypass（门禁绕过检测）+ verifyCoachExecution 统一入口 |
| `coach/stageOrchestrator.ts`（扩展） | evaluateAndAdvanceStage + attemptArtifactSynthesis 接收并检查 policyGate.blocked 硬阻断；processAgentResponse 的 action/intent 白名单上提到 postExecutionVerifier |
| `coach/coachOps.ts`（扩展） | logCoachPolicyExecution 加绕过检测：policyGate.blocked + LLM 声明推进类 action → 记 gate_bypass_attempt 审计 |
| `tests/post-execution-verifier.test.mjs` | 14 测：硬阻断判断 + action/intent 白名单 + 绕过检测 + 统一入口 |
| `tests/gate-bypass-detection.test.mjs` | 2 集成测：policyGate 阻断+LLM 声明 rewrite → 记绕过审计；声明 none → 不记 |

## 关键技术决策表

| 决策 | 理由 |
|------|------|
| 硬阻断只阻断推进/合成，不阻断对话 | evaluateAndAdvanceStage/attemptArtifactSynthesis 检查 policyGate，但 orchestrateCoachMessage 仍调 routeToStageAgent 让 LLM 回应——门禁严格但不冷暴力 |
| 后验层抽纯函数 | shouldBlock/detectBypass/sanitize 抽离可测，stageOrchestrator 私有函数难直接测；纯函数 14 测覆盖核心逻辑 |
| 绕过检测审计 gate_bypass_attempt | policyGate.blocked 但 LLM 声明 rewrite/run-full-cycle 等推进类 action → 记审计，为门禁严格遵守提供可观测性（非阻断 LLM 回复，只记录） |
| action/intent 白名单上提 | processAgentResponse 内联 validActionSet/validIntentSet 上提到 postExecutionVerifier，统一后验入口 |

## 遗留问题

- 无（V3 纯门禁逻辑硬化，无外部依赖风险）

## 对后续版本的约束

- 门禁硬阻断确立：用户配置严格策略（requireHumanConfirmation）时会频繁被卡，需在文档说明策略配置后果
- postExecutionVerifier 可被 V4 本体回流复用（本体变更校验）
- gate_bypass_attempt 审计为门禁遵守度提供可观测指标
