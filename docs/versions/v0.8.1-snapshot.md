# v0.8.1 Snapshot — V2.2 第二步：codeRewrite 异步化 + 编码 agent 接入

> 状态: 已归档 snapshot（2026-06-25，verify:all 全绿）

## 版本目标

把 codeRewrite 从「LLM 生成完整文件→writeFileSync 写盘」改造为「ClaudeCodeCliAgent 真实改代码→git diff 提取→assertBoundaryWhitelist 事后校验越界回滚」。异步 job 封装，保留同步 LLM 路径为 fallback。dryRun 实跑留用户手动触发（脚本+步骤已交付）。

## 关键技术决策表

| 决策 | 理由 |
|------|------|
| 范式转变：事前约束→事后校验 | LLM 路径在写入前 assertBoundaryWhitelist 校验输出路径；编码 agent 自由改→git diff 提取改动→事后校验越界回滚（git checkout） |
| CodeRewriteGitOps 接口抽象 | listChangedPaths/readFileContent/revertFile 注入，生产用真实 git，测试用 mock（用户选 mock 测，实跑留手动） |
| dryRun 走同步 LLM fallback | dryRun 是"预览不写盘"，编码 agent 真实改代码不兼容 dryRun 语义；非 dryRun 才走编码 agent |
| fire-and-forget 执行器 | startCodeRewriteJob 创建 job 后不 await 执行器，后台跑完更新 job 状态；路由立即返回 jobId |
| 保留同步 rewriteCodeInBoundary | 无 codingAgentRegistry 配置时走原 LLM 生成文本写盘路径，零回归，不阻断现有功能 |
| BUILDWISE_CODING_AGENT_ENABLED=1 默认开 | claude CLI 已确认可用；可设 0 关闭回退纯 LLM |

## 遗留问题

- **dryRun 实跑未验证**：编码 agent 真实改代码的端到端流程由 dryrun-code-rewrite.mjs 脚本交付，需用户在真实 git repo + 边界白名单上手动触发验证（消耗 claude LLM 额度，分钟级耗时）
- stream-json 事件格式的精确性：mock 测试基于已知格式，实跑时若 claude stream-json 格式有差异需微调 mapStreamEvent
- codeRewriteJobStore 是 in-memory（进程重启丢失），与 analysis job 一致；持久化留待后续（与 JSON 持久化债务一并处理）

## 对后续版本的约束

- 编码 agent 改动（git diff）将作为 V4 本体回流的输入（codePaths 更新）
- CodeRewriteGitOps 接口可扩展为其他 VCS（未来若支持非 git 仓库）
- 编码 agent 范式确立后，V3 门禁后验层可复用事后校验模式
