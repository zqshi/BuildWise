- **盘点 16 表**：从 `domain/workspace/repository.ts` + `collaborationTypes.ts` 枚举所有持久化表/集合，确认哪些已有 tenant_id、哪些缺失

  - 系统巡检（experience scan 等）tenant-agnostic 旁路（超管/系统任务跨租户，不能被 tenant scope 误拦）
- **owner 语义衔接**：v0.22.0 真超管 platformRoleBinding 跨租户 admin 须在 DB scope 层有对应旁路（否则硬隔离反拦真超管）

## 对后续版本的约束
- DB 硬隔离后，tenantAccess 应用级判定（v0.22.0）保留作快路径，DB 层兜底，两层不互斥
- 16 表 tenant_id 一旦硬隔离，新增表必须带 tenant_id 列（schema 纪律）
- 真超管跨租户访问须 DB scope 层显式旁路，不可依赖应用层漏判
