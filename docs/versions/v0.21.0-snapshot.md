## 版本目标
v0.18.0 遗留「fetchJSON/useAuthController 副作用未单测，受限于 node --test 不解析无扩展名值 import」。立项前核实限制真实：node v25.9.0 `--experimental-strip-types` 对 `fetchJSON.ts` import `../auth/tokenStore`（无扩展名）报 `Cannot find module`。本版解此限制（tsx loader + jsdom 前端全局），并补 fetchJSON 403 dispatch 副作用单测（触发点）。

## 交付内容摘要
- **T1 解 node --test 无扩展名 import 限制**（done）：test script 改 `c8 node --import tsx --test`（替换 `--experimental-strip-types`）。tsx（devDep 已有 `^4.22.4`）用 esbuild 解析 TS 无扩展名 import。现有 225 测试无回归。验证：`import fetchJSON.ts` 成功（原报 Cannot find module）。
- **T2 fetchJSON 403 dispatch 副作用单测**（done）：引入 jsdom（devDep）提供 window/localStorage。`fetchJSON.test.ts` 2 用例：①403 非 auth 路由 dispatch `buildwise:tenant-stale` ②403 auth 路由不 dispatch。mock fetch + spy window.dispatchEvent。token 为 null 时跳过 ensureFreshToken，空 localStorage 隔离 LLM/网络。

## 关键技术决策表
| 决策 | 选择 | 理由 |
|---|---|---|
| 无扩展名 import 解法 | tsx loader（`--import tsx`） | 替换 `--experimental-strip-types`；小侵入，现有 node:test API 不变；全局改 import 加 .ts 扩展名风险高 |
| 前端全局（window/localStorage） | jsdom 注入 global | fetchJSON 用 bare window/localStorage，node 默认无；jsdom 提供 |
| fetchJSON 测试隔离 | mock fetch + spy dispatchEvent + 空 localStorage | token null 跳过 ensureFreshToken，不调 LLM/网络 |
| T3 useAuthController hook 单测 | 转后续专项 | 需 @testing-library/react 基础设施升级，专项版本做更稳妥 |

## 遗留问题
- **T3 useAuthController hook 副作用单测**（转后续专项）：useAuthController 是 React hook，tenant-stale→refreshSession 副作用测试需 `@testing-library/react`（renderHook+waitFor+act）+ mock fetch session API + 设 in-memory token（tokenStore.saveTokens）+ jsdom，涉及 fetchAuthSession/workspaceApi/API_BASE/sameOriginProxy 多细节。引入 @testing-library/react 是前端测试基础设施升级，专项版本做更稳妥。
- **fetchJSON.test.ts jsdom global setup 内联**：当前在测试文件顶部 setup `globalThis.window/localStorage`。后续测试文件多了应提取 `tests/setup.ts` + `node --import` 加载（避免 global 污染）。
