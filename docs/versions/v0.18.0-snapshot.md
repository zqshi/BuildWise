# v0.18.0 Snapshot — 多租户列表 403 止血 + 前端 tenantId 治本

> 状态: 已归档（2026-06-27）
> 起始 commit: c0fe079 (2026-06-27)
> 上一版本: [v0.17.0](v0.17.0-snapshot.md)

## 版本目标
v0.17.0「堵数据串」让前端 `fetchJSON` 统一注入 `x-tenant-id` header 后，暴露 `GET /projects` 在「前端 tenantId 与后端租户成员状态不同步」时返回 403、前端报「项目数据加载失败」阻断用户。本版本止血+治本：后端列表接口放宽 tenantId 门禁为空列表降级；前端注入 tenantId 前过滤失效值并在租户失效时主动同步 session。

## 交付内容摘要
- **T1 后端止血**：`handleListProjects` 去 tenantId 前置 403 门禁，脏/失效 tenantId 降级为空列表而非 403。契约 `invalidTenantSelection` 403→200[] + 新增「无权 tenantId 返回空列表」测试。
- **T2 前端治本（A+B）**：A 迁移根治——`authTenantSession` 迁 `infrastructure/auth/tenantSession.ts`（DDD 合规），`fetchJSON` 注入 x-tenant-id 前用 `resolveCurrentTenantId` 过滤挡伪造/残留脏值；B 403 事件刷新——`fetchJSON` 遇 403（非 auth 路由）dispatch `buildwise:tenant-stale`，`useAuthController` 监听→`refreshSession` 拉最新 tenants 修正后端失效脏值（防循环）。
- **T3 owner 分支收敛**：方案B（resolveTenantRole 加 platformOwner 旁路 + 删 ensure*Access owner 块）实施后契约回归（AUTH_MODE=off dev 用户 authRole=owner 但无 platformRoleBinding，旁路不触发 → policy execute 403）。**已 revert**，转 backlog 待重新设计。

## 关键技术决策表
| 决策 | 选择 | 理由 |
|---|---|---|
| list tenantId 门禁 | 去前置门禁,靠 listProjectsForUser 过滤降级 | 读列表不因 tenantId 拒绝;canRead 走具体 projectId,脏值只得空列表不越权 |
| 前端 tenantId 注入 | resolveCurrentTenantId 过滤后再注入 | 挡 localStorage 脏值直发;infrastructure 层复用 shared 纯函数 |
| 403 处理 | dispatch tenant-stale→refreshSession | 事后修正后端失效脏值,参照 auth-expired(401) 模式 |
| T3 owner 收敛方案B | revert,转 backlog | platformRoleBinding 旁路与 AUTH_MODE=off authRole=owner 语义不等价,破坏 dev/契约场景;需重新设计 |
