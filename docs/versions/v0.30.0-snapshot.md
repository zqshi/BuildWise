## 版本目标

## 关键技术决策

| 决策 | 理由 |
|------|------|
| 编造防控：有数据端漏评→block，无数据端降级整体 conclusion | 规避 v0.29.0 编造教训——LLM 不得在无按端真实依据时编造独立按端结论；有数据（测试用例或代码白名单）端必须独立评审 |
| 编造防控逻辑移入 releaseReviewOps（从 governanceRunnerOps 抽出） | perPlatform 评审核心内聚 + 两条链（governance 主 + qualityAudit）复用同一纯函数；签名重构为 ReleaseReviewFinalizeContext 全可选 |
| summarizeTestMatrixByPlatform 接入 synthesizeReleaseReviewOp 数据段 | T1 死代码（无调用方）的唯一合法归宿——作为 LLM 按端评审真实依据，否则删除 |
| T2 是端级门禁「统计层」非越界「阻断层」 | assertBoundaryWhitelist（越界阻断，agent 改写回滚+发布越界校验依赖）不改；"改 web 路径不视为 ios 完成"是端级完成度统计，与 T1 对称 |
| codePathsByPlatform 平行字段（最小侵入） | 保留 codePaths 平铺 → 20+ 读写点零改动，旧数据降级不分端 |
| qualityAudit 链不补独立 LLM mock（仅 prompt 装配纯函数测试） | runQualityAuditAgent 用模块级 import runAnalysisPrompt 非 deps 注入，补 mock 需改签名侵入可选默认关路径；finalize 纯函数已被主路径 mock 覆盖 |
| 修复既有 lint error（非本版本引入） | 归档要求 verify:all 全绿；既有债（非空断言/隐式 any）+ T1/T2 useImportType 阻断，归档前修复 |

## 对后续版本的约束

- 按端质量数据（测试矩阵/代码路径）为 LLM 按端评审的必要前置，不得在数据未齐备时让 LLM 编造按端结论（v0.29.0 T3 转后续的教训）；
- perPlatform 数据须有按端真实依据（测试覆盖/代码归属），非 LLM 推断；
- TargetPlatform 固定枚举不变，新增端加枚举值；
- 编造防控（finalizeReleaseReviewPerPlatform）为发布评审结构一等后处理，两条链（governance 主 + qualityAudit）须对齐，不得绕过。
