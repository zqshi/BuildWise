# v0.25.0 Current — 本体评审解决流程（v0.24.0 评审门禁升级前置）

> 状态: 进行中
> 起始 commit: 21bb1e8 (2026-06-28)
> 上一版本: [v0.23.0](v0.23.0-snapshot.md)

## 版本目标
v0.24.0 激活了本体发布门禁，但评审门禁受限于 ReviewTask 无解决路径——当前语义是"候选态阻断+发布即认可"（published 不查历史 blocking）。本版建本体评审解决流程：用户确认术语/规则后清除对应 blocking 评审，使 candidate→publish 前须解决阻断评审。完成后评审门禁从"发布即认可"升级为"发布前须解决阻断评审"，让本体评审真正独立阻断，夯实核心价值（活的知识链条的本体质量门禁）。

## 版本验证标准
1. 用户可对单个 ReviewTask 标记"已解决"，对应 blocking 评审从快照移除
2. candidate 快照有未解决 blocking 评审时 publish 被门禁阻断（需先解决）
3. 全部 blocking 解决后 publish 放行，且 published 后评审门禁不再因历史 blocking 误阻

## 版本范围

- T1 评审解决流程设计 + Red 基线（resolveReviewTaskOp 纯函数 + 持久化）
- T2 评审门禁语义升级（candidate 有未解决 blocking 阻断 publish；evaluateOntologyReleaseGate 调整）

## T1 实施要点（pending，起步先读全 continuousModelingService + ReviewTask 持久化现状）

核查事实（v0.24.0 已坐实）：
- buildReviewTasks 生成 blocking=true 评审（术语变更/规则缺失），无解决路径。
- publishSnapshot 不清除 blocking 评审；onAnalysisConfirmed 自动 publish。
- v0.24.0 评审门禁语义：candidate 有 blocking 阻断（T2b 已实现），但 published 不查历史 blocking（发布即认可）。

T1/T2 目标：建 resolveReviewTaskOp（标单个评审已解决 → 从快照 blockingReviewTasks 移除/标 resolved）；publishSnapshot 前检查 candidate 无未解决 blocking；published 后评审门禁仍不因历史 blocking 误阻（保持 v0.24.0 发布即认可的 published 路径，但 publish 前置加阻断）。
