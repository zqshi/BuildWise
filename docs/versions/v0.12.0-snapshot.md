## 关键技术决策表

| 决策 | 理由 |
|------|------|
| 三 scenario 路径 /api/→/api/v1/（replace_all） | 路由整体迁 v1（app.ts:241-252），`/ready` `/metrics` `/health` 根级不含 `/api/` 自动不受影响；单趟 replace_all 不产生 /api/v1/v1/ |
| 删 custom_roles 下划线断言 | 路由全域无 custom_routes 别名（grep 确认），非 legacy 兼容，是过时债务 |
| setErrorHandler 优先 error.statusCode | Fastify schema 校验失败抛 ValidationError(statusCode=400)，原代码用 reply.statusCode（默认 200）误判 500；custom_roles 手动校验返回 400 不受影响（不走 schema） |
| buildReleaseEnv 补 ANTHROPIC_* | ClaudeCodeCliAdapter 用 ANTHROPIC_BASE_URL/AUTH_TOKEN/MODEL，buildReleaseEnv 只清 LLM_API_* 漏 ANTHROPIC_*，继承 process.env 真实配置导致 analysis 调真实 glm-5.2 限流 502；屏蔽后 analysis 走 503 降级，契约跳过 LLM 依赖断言 |
| gitIntake :64 改 pending-confirmation | f5ea645 新建 iterationCoreOps 时设 "available"，但 gitIntakeOps:226 仍检查 pending-confirmation，两者不一致导致创建后 coach 不处理；pending-confirmation 与契约:120 + coach 设计一致 |
| :232 unknown 返回 pendingConfirmationResponse | pending-confirmation + 中性消息（如"继续"）原 return null 让 coach 走 LLM 路径，LLM 屏蔽时 503；契约:142 期望 200+guidance（确定性提示），故 unknown 返回含 suggestedActions 的 guidance response |
