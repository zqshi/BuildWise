## 版本目标

v0.30.0 让 `releaseReview.perPlatform` 数据流入前端按端展示（编造防控 + 两链对齐 + UI 就绪），但端到端链路仅在单元测试+mock 层验证（670 测试 0 fail），**从未在真实环境（真实 LLM + 真实附件分析 + 前端渲染）跑通**。本版本在真实环境实跑声明多端项目 → 分析附件 → LLM 按端评审产出 perPlatform → 前端按端渲染全链路，验证 v0.30.0 交付在真实环境有效，修复实跑暴露的真实问题。

**性质**：验证+按需修复，非新功能开发。单元测试已覆盖确定性逻辑（编造防控纯函数/解析/聚合）；实跑额外验证的是真实 LLM 按端评审产出质量 + API 序列化往返 + 前端渲染连贯性。

## 版本验证标准

1. 声明多端（web+ios）的项目，真实分析后后端 `releaseReview.perPlatform` 非空，每端有 decision/blockers（非降级整体）；
2. 有按端数据端（测试用例或代码白名单）被独立评审，无数据端降级整体结论（编造防控在真实 LLM 产出下生效，不编造）；
3. 前端分析报告 `AnalysisReportAdvancedSections` 按端渲染各端评审结论（`perPlatformRows.length>0` 不降级整体展示）。

## 各任务实施要点

### T1 — 实跑环境就绪
- **LLM 配置确认**：`.env` 存在且 LLM_API_BASE/KEY/MODEL 已 set，但 `.env.example` 默认 deepseek。须确认 `.env` 实际为智谱 GLM（glm-5-turbo/glm-5.1/glm-4.5-air 分层，与后端同源，记忆 feedback_llm_model_zhipu 约束）。若非智谱，改回智谱配置。
- **造多端项目**：`reset-business-environment.mjs` 造的项目**无 targetPlatforms**（单端默认 web），实跑"按端"需声明多端。两条路径：①改 reset 脚本造的项目加 `targetPlatforms: ["web","ios"]`；②reset 后用 API `POST /projects` 传 targetPlatforms 补造。优先②（不改 seed 脚本，更灵活）。
- **启动服务**：后端 `cd v2/backend && npm run dev`（端口 5055）+ 前端 `cd v2 && npm run dev`（vite）。后台跑，盯启动就绪日志。
- **造有按端数据的附件**：上传能触发 synthesizeTestMatrixOp（生成按端测试用例）+ synthesizeCodePathsByPlatformOp（标注按端代码路径）的附件，让 perPlatform 有真实按端依据（非编造）。

### T2 — 后端 perPlatform 端到端实跑验证
- **触发分析**：`POST /iterations/:id/uploads/...`（上传）+ `POST /iterations/:id/analyze`（`analyzeAttachment` 同步 await，非异步 job）。
- **同步分析耗时**：一次完整分析多次 LLM 调用（synthesizeTestMatrixOp + synthesizeCodePathsByPlatformOp + synthesizeReleaseReviewOp + governance agents），分钟级。HTTP 可能超时——盯后端日志看 synthesizeReleaseReviewOp 产出，或加大 timeout。
- **验证点**：分析完成后查 iteration.changeControl.releaseReview（或 analysis report）的 `perPlatform`——非空 + 每端 decision/blockers。
- **编造防控真实生效**：有数据端（测试用例或代码白名单 ruleCount>0）LLM 漏评→finalize 补 block；无数据端→降级整体 decision。观察真实 LLM 是否按 prompt 逐端评审（不可控，靠 finalize 兜底）。
- **主路径确认**：USE_CONSOLIDATED_AGENTS 默认 false → runQualityGatePhase→synthesizeReleaseReviewOp 是主路径（非 qualityAudit 可选路径）。

### T3 — 前端按端展示渲染验证
- **渲染入口**：`AnalysisReportAdvancedSections.tsx:31` 调 `describeReleaseReviewPerPlatform(releaseReview?.perPlatform)`，:148 `perPlatformRows.length>0` 才按端渲染，否则降级整体展示。
- **验证点**：T2 产出 perPlatform 后，前端分析报告 drawer 渲染出按端行（各端「通过/有条件通过/阻断」+ 阻断项/就绪描述），非整体单一结论。
- **序列化往返**：perPlatform 从后端 releaseReview → API → 前端 state → 组件，验证完整无损（类型前后端对齐，tsc 0，但真实往返未验证）。
- **截图/日志为证**：实跑渲染截图或 DOM 检查作为验证证据。
