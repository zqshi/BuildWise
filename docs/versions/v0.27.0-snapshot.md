- **T1 A→B 回写改造为正名规范**（done）：调研推翻"回写空转"初判——回写有真实功能（HTTP `saveCandidate` 入口让前端直传本体项，publish 时沉淀回 KB），但绕过正名链（`extractKnowledgeBaseUpdateOp` 的碰撞检测/增量统计/审计）是数据源单一性真问题。直接复用 `extractKnowledgeBaseUpdateOp` 不可行（强耦合分析报告追溯结构，快照 rules/entities 无法映射）。落地为"改造为正名规范"：`snapshotToKbPatch` 增强 key trim 归一（修 KB 项含空白时重复沉淀 bug）+ 返回增量统计 + `publishSnapshot` 写审计日志 `ontology.snapshot-merged`。保留合并功能，现有回写测试不破坏。TDD 2 例 + 全量 603 单测 + 契约通过。
- **T2 per-prefix 超限文件拆分**（done）：4 核心高风险文件拆至软限内，统一策略"拆非导出辅助、导出留原文件"——导出接口零变化、零调用方改动、零测试改动、零桥接层（避免 v0.17.0 re-export 桥接债务重蹈）。
  - `synthesisTaskOps.ts` 399→256：6 prompt 构建/解析辅助 → `synthesisTaskPromptOps.ts`

  - `analysisOps.ts` 530→228：6 分析管道阶段函数 → `analysisPipelineOps.ts`（阶段间 ReturnType 链式依赖同文件保持）
  - `ontologyService.ts` 455→141：类型分离破循环 → `ontologyTypes.ts`（共享类型）+ `ontologyExtractionOps.ts`（8 字段提取）；2 导出留原文件零桥接
  - 全量 603 单测零回归，typecheck/lint 全清。`!` 改类型守卫；拆分引入的 useImportType（biome 1.9 对 `ReturnType<typeof>` 误报）以 biome-ignore 说明处理。
- **T3 前端 Props Drilling 残留评估**（done，评估型无代码改动）：Props Drilling 已大幅收敛，v0.17.0 的 55 props（24 状态+31 回调）→ ProjectsWorkspace 仅 10 个全可选展示字段，状态/回调全迁 `AppControllerContext`。`ProjectsWorkspaceConnector`（薄壳）零 prop 透传，证实 drilling 已切断。残留 10 个 Connector 不传的"预留接入"占位（5 个传子组件 `ProjectOverviewPanel` 走默认值 + 5 个 `_` 前缀完全不用）转后续评估。

## 关键技术决策表
| 决策 | 选择 | 理由 |
|---|---|---|
| T1 回写处置 | 改造为正名规范（非删除非复用 extractKnowledgeBaseUpdateOp） | 回写有真实功能但绕过正名链是数据源单一性真问题；直接复用强耦合分析报告追溯结构、快照 rules/entities 无法映射，不可行 |
| T1 key trim 归一 | `snapshotToKbPatch` 增强 trim + 增量统计 + 审计日志 | 修 KB 项含空白时重复沉淀 bug，正名链 trim 归一一致性，沉淀可审计可统计 |
| T2 拆分策略 | 拆非导出辅助、导出留原文件 | 导出接口零变化、零调用方改动、零桥接层，避免 v0.17.0 re-export 桥接债务重蹈 |
| T2 ontologyService 类型分离 | 拆 `ontologyTypes.ts` 共享类型 | 破 ontologyService 与 extractionOps 互引的循环依赖 |
| T2 useImportType 处理 | biome-ignore 说明（非改 type import） | biome 1.9 对 `ReturnType<typeof>` 误报，typeof 需 value import 不能改 type |
| T3 残留占位处置 | 转后续评估（本版不删不接） | T3 为评估型；5 个 `_` 完全不用的占位是 v0.17.0 保留 10 版本未接入的预留 stub，后续评估接入或 YAGNI 删除 |
