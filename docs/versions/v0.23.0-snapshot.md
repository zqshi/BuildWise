## 版本目标
v0.22.0 owner 语义收敛后，从应用级软隔离升级到 DB 级硬隔离。T1 探路重塑方向（非原 backlog「16 表加列」）：实际 ~23 表多为 payload blob/JSON 集合，加列无意义；真实方案是修 syncTypedTables 漏写 projects.tenant_id 的核心 bug + 给关系型 typed table 查询加 tenant scope（SQL WHERE/JOIN 过滤），从根上杜绝跨租户数据串——应用层漏判时 DB 层兜底。

## 交付内容摘要
- **T1 探路**（done，commit 1935257）：表枚举（~23 业务表+2 系统表，分三类：2 有 tenant_id 列/~16 无列靠 project_id 链式/1 JSON blob）+ 双轨存储坐实（workspace_collections JSON + typed tables 关系型双写）+ 核心 bug 定位（projects.tenant_id 列存在但 syncTypedTables 从不写入）+ 策略选定（修 bug + JOIN 过滤，非 16 表全加列）。
- **T2 写入层修复**（done，commit 2a327cb）：sqliteWorkspaceCore 三处 projects 写入点加 `item.tenantId ?? "default"`——insertProject:329 / updateProject:335 / syncTypedTables:407-409。修复前列永远 'default' 致 searchKnowledgeAcrossProjects 失效。TDD Red（租户A 搜索返回空）→ Green。
- **T3 查询层硬隔离**（done，commit 3f1ba45-21bb1e8）：ProjectRepository listProjects/findProject 加可选 tenantId 参数（向后兼容）；sqlite 层 SQL WHERE 过滤；listProjectsForUser 接入 DB 兜底；mock-factories 同步。TDD Red（跨租户查返回/不串）→ Green。
- **T4 归档验证**（done）：verify:all 全绿 566 测试，6 项质检全过，分层入库。

## 关键技术决策表
| 决策 | 选择 | 理由 |
|---|---|---|
| 隔离范围 | 仅 projects 表（不 23 表全加列） | ~16 表无 tenant_id 列靠 project_id 链式关联，payload blob/JSON 集合加列无数据；靠 JOIN projects 过滤 |
| 写入层 | 三处 projects 写入点加 tenant_id | 002 已加列只缺写入，可能不需新 migration |
| 查询层签名 | 可选 tenantId 参数（不强改） | findProject 有 40 调用方，强改破坏面太大；可选参数向后兼容，真超管/系统巡检不传 |
| 查询层语义 | 不传=全表（兼容）/传=WHERE 过滤（兜底） | 应用层 listProjectsForUser 已有过滤，DB 层作漏判兜底，非取代 |
| 真超管旁路 | 不传 tenantId（走全表路径） | isPlatformOwner（v0.22.0）场景不传 tenant，DB 层不阻断 |
| workspace_collections JSON | 保持应用层覆盖 | JSON blob 无法 SQL 过滤，查询走 readCollection+内存 filter，应用层已覆盖，非隔离漏洞点 |

## 遗留问题
- **listIterations/findIteration/listMessages/listAuditLogs 未加 tenant scope**：T3 聚焦 projects 表（租户边界根）。这些表靠 project_id 链式关联，跨租户风险低于 projects 全表扫，且应用层 tenantAccess 已覆盖大部分路径。留后续按需扩展（若发现跨租户串的调用方）。
- **assistant_messages 的 tenant_id 是否真生效**：T1 标注待验证（schema 008 有，查询是否用上未逐一核实）。
- check:boundaries 软限 warning（既有文件，非本版引入）。

## 对后续版本的约束
- DB 硬隔离后，tenantAccess 应用级判定（v0.22.0）保留作快路径，DB 层兜底，两层不互斥
- 新增关系型 typed table 查询默认应支持可选 tenantId（schema 纪律）
- 真超管跨租户访问走"不传 tenantId"路径，DB 层显式旁路，不可依赖应用层漏判
