## 各任务实施要点

### T1 — 本体 publish 覆盖 bug 修复
**起步**：先产品判断 candidate id 策略——
- 方案A：禁止 publish 后同 iteration 再 saveCandidate（简单，但限制重做迭代本体建模）
- 方案B：candidate id 含版本序号 `snapshot-${projectId}-${iterationId}-v${n}-candidate`（允许多版本候选，不覆盖 published）

核查 saveCandidate 调用方（onAnalysisConfirmed 回调 app.ts:206/221、REST continuousModelingRoutes），评估改动穿透。TDD Red 先行（publish 后同 iteration saveCandidate 不覆盖 published）。

### T2 — mock/真实 repo 语义一致
`createInMemoryModelingRepo.saveCandidateSnapshot` 由 push 改 upsert（对齐 JsonContinuousModelingRepository）；既有 `saveCandidate diff against published baseline` 测试依赖 mock push 掩盖，改为符合真实 repo 行为（第二次 saveCandidate 用不同 iterationId 或 T1 后 candidate id 不覆盖）。

### T3 — onAnalysisConfirmed 集成测试
补 app.ts 装配层测试：`confirmIterationAnalysis → 回调 → saveCandidate（生成 blocking）→ 自动 publishSnapshot → T2 门禁阻断停 candidate`。现有 confirmIterationAnalysis 测试用孤立 service 未注册回调，需 e2e 或装配层测试。

### T4 — typed table tenant scope
核查 listIterations/findIteration/listMessages/listAuditLogs 调用方跨租户串风险，按 v0.23.0 T3 策略加可选 tenantId 参数（向后兼容）+ DB 兜底。

### T5 — assistant_messages tenant_id 核实
schema 008 有 tenant_id，核实查询是否用上（listAssistantMessages 等是否 WHERE tenant_id）。

### T6 — useAuthController hook 副作用单测
引入 @testing-library/react，hook dispatch/副作用单测（v0.21.0 T3 遗留）。
