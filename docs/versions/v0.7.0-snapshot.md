# v0.7.0 Snapshot — V2.1 Agent 适配器抽象 + 注册表

> 状态: 已归档 snapshot（2026-06-25，verify:all 全绿）

## 版本目标

建立 CodingAgentAdapter 端口 + AgentRegistry 注册表（参照 arc `adapter.py`/`registry.py`），让编码 agent 框架可声明式切换。与 AgentRunner（LLM 单次对话）并存不替代。这是「OpenClaw 不强依赖、可切换任何框架」的声明层落地。

## 交付内容摘要

| 文件 | 内容 |
|------|------|
| `domain/shared/codingAgent.ts` | CodingAgentAdapter 端口（start/getStatus/getEvents/cancel/close + agentType/implemented）+ CodingTaskContext/CodingSessionStatus/CodingAgentEvent 类型 + isCodingAgentAvailable 能力检测。参照 arc `adapter.py` |
| `infrastructure/agent/agentRegistry.ts` | AgentRegistry 注册表（register/create/availableAgents/isAvailable/clear）。参照 arc `registry.py`，create 时校验 implemented |
| `infrastructure/llm/llmProviderRegistry.ts` | LLM provider 注册表（registerLlmProvider/resolveLlmRunner/registeredLlmProviders），key 用 string 支持未来任意 provider |
| `infrastructure/llm/agentRunnerFactory.ts` | createAgentRunnerFromEnv 委托 registry，抽 resolveTimeoutMs/resolveMaxOutputTokens，模块级注册 OpenAI/Anthropic 两 provider。行为零变更 |
| `backend/tests/coding-agent-adapter-contract.test.mjs` | 12 契约测试：registry 行为 + mock adapter 完整契约 + 能力检测 + 声明运行时分离验证 |
| `backend/tests/llm-provider-registry.test.mjs` | 5 测试：默认 provider 注册 + 可扩展性 + factory 守卫 |

## 关键技术决策表

| 决策 | 理由 |
|------|------|
| CodingAgentAdapter 与 AgentRunner 并存不替代 | AgentRunner 管同步单次 LLM 对话（教练/合成），CodingAgentAdapter 管异步会话式编码执行（改代码），职责不同 |
| 能力检测用接口形态（isCodingAgentAvailable）而非 instanceof | 沿用 isGatewayCapableRunner 模式，解耦具体实现 |
| AgentRegistry.create 时校验 implemented | 注册表存 factory，create 调用时检查实例 implemented，未实现抛错（arc 在注册入口预检，BuildWise 在 create 时检） |
| llmProviderRegistry key 用 string 而非 LlmProvider 联合 | 支持未来注册任意 provider（如 openclaw-gateway），LlmProvider 联合保留作已知默认，不限制注册表扩展 |
| CodingTaskContext 字段对齐 codeRewriteOps 的 RewriteContext | repoPath/instruction/boundaryCodePaths/role/acceptanceCriteria/maxFiles，V2.2 改造 codeRewrite 时平滑接入 |

## 遗留问题

- 无（V2.1 纯声明层，不接真实 CLI，无运行时风险）

## 对后续版本的约束

- **CodingAgentAdapter 是编码 agent 唯一端口**：业务层禁止直接 import 具体适配器实现，必须通过 AgentRegistry.create(type)
- **v0.8.0（V2.2）选型待确认**：第一个具体适配器是 ClaudeCodeCliAdapter（推荐）还是 OpenClawCodingAdapter（调 OpenClaw Gateway，不改其源码），适配器抽象不变
- **声明+运行时分离**：domain 定义端口，infrastructure 实现适配器，业务层只依赖端口
- **LLM provider 扩展**：未来加 provider 只需 registerLlmProvider，不改 createAgentRunnerFromEnv
