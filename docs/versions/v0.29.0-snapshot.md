## 版本目标

引入「目标端」一等维度，让发布评审按端分别给 decision/blockers，整体可发布 = 各声明端均 `go`，在门禁层堵死虚假 go（多端项目下整体 go 掩盖单端短板——web 端测试撑高整体 passRate、原生端零覆盖被合法掩盖）。能力边界：不替代各端 CI/构建，「真实投产可用」= 交付物归属端 + 门禁按端聚合。

## 关键技术决策

| 决策 | 理由 |
|------|------|
| TargetPlatform 固定枚举（非开放字符串） | 端集合有限稳定，类型安全 |
| targetPlatforms 持久化零迁移（JSON blob 往返） | Project 序列化结构自动含新字段，无 schema 变更 |
| 门禁端级聚合用纯函数（assessPlatformDeliveryReadiness） | 确定性规则，零 IO，可单测，堵虚假 go 不依赖 LLM |
| publish 门禁 guard `declaredPlatforms?.length>0` 才启用端级门禁 | 向后兼容：未声明端的旧项目走整体门禁 |
| 前端不复制 normalizeTargetPlatforms（UI 只管传数组） | 后端 normalize 兜底，前端避免死代码 |
| 抽共享 TargetPlatformsPicker 组件 | 创建表单 + 编辑器复用 chip 逻辑 + label map，DRY |
| T3 LLM 按端评审转后续 v0.30.0 | 缺按端真实质量数据（测试矩阵/代码路径按端分组是 v0.30.0），无数据下 LLM 按端评审为编造推断违反「不造假」；门禁 T4 确定性堵死虚假 go 不依赖 T3 |
