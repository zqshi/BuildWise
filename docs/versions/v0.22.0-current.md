## T1 实施要点
- 探路三类 owner 语义：
  - **真超管 platformRoleBinding**：平台级绑定（governance/platformRoleBindingOps），应可访问所有租户
  - **dev 默认 owner**：AUTH_MODE=off 时 runtimeAuth 默认 role=owner（runtimeAuth.ts:88-96），开发/契约场景
  - **租户 owner**：resolveTenantRole（tenantAccess.ts:52）返回 admin（tenantId===userId 或 tenantMemberBinding admin），租户内 owner
- **核心矛盾（已坐实）**：ensureProjectAccess/ensureIterationAccess 的 owner 块（workspaceRouteUtils.ts:61-82/108-135）只放行**无 tenantId 项目**（dev owner）；有 tenantId 项目走 getProjectAccess→resolveTenantRole 无 platformRoleBinding 旁路 → 真超管跨租户 403
- **v0.18.0 方案B 错误根因**：删 owner 块 + 加 platformOwner 旁路 → dev owner 访问无 tenantId 项目失放行 → 403（revert 原因）
- **v0.22.0 设计方向**：保留 owner 块（不动）+ 加 platformRoleBinding 旁路（resolveTenantRole 加 isPlatformOwner，真超管跨租户 admin），修正方案B 删块错误
- **真超管识别**：platformRoleBinding role normalize（LEGACY_ROLE_MAP admin→owner）=== "owner"
- **实现素材**：resolveTenantRole(tenantAccess.ts:52) 加 isPlatformOwner 旁路；repo.listPlatformRoleBindings(已有)；mock repo(mock-factories.mjs:209)；现有 tenant-access.test.mjs 可复用 pattern
- **T2 接续要点**：TDD Red（真超管 role=admin 访问有 tenantId 非自己租户项目 → canRead 应 true，当前 false）→ Green（resolveTenantRole 加 `if (isPlatformOwner(repo, userId)) return "admin"`，保留 owner 块不动）→ 契约验证不破坏 dev/契约（AUTH_MODE=off authRole=owner 场景）

## T2 实施结果（done 2026-06-28）
- **Red**：tenant-access.test.mjs 加「平台超管可跨租户读写非自己租户的项目」→ 真超管 super-admin 访问 owner-a 租户项目 canRead 期望 true 实际 false（核心矛盾坐实）
- **Green**：tenantAccess.ts 加 `isPlatformOwner(repo, userId)`（platformRoleBinding role=owner/admin），`resolveTenantRole` 顶部加旁路 `return "admin"`；owner 块（workspaceRouteUtils.ts）**未动**
- **三类 owner 语义收敛**：真超管（platformRoleBinding 旁路跨租户 admin）/ dev owner（AUTH_MODE=off authRole=owner 走 owner 块放行无 tenantId 项目）/ 租户 owner（tenantId===userId 返回 admin）
- **不破坏验证**：保护性「平台级 member 不获得超管权限」绿；既有 outsider/platform-member 绿；契约测试（contract-owner AUTH_MODE=off）全 200；全量单测 550 绿；tsc --noEmit 零错误
- **修正方案B 根因**：方案B 删 owner 块 → dev owner 失放行 403；v0.22.0 保留 owner 块 + 加旁路，dev owner 与真超管各走各路
