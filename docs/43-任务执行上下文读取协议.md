# 任务执行上下文读取协议

## 目标

- 确保每次执行任务前先读取关键上下文，避免“脱离规范开发”。
- 确保不同执行者输出质量一致、边界一致。

## 强制读取顺序（不可跳过）

1. `docs/10-产品顶层设计（执行版）.md`
2. `docs/20-技术架构设计（执行版）.md`
3. `docs/20-DDD分层与边界规范.md`
4. `docs/40-工程执行标准（技术栈与模式）.md`
5. `docs/42-研发治理规范（DDD-TDD-质量门禁）.md`
6. `docs/30-目标驱动自举执行蓝图.md`

## 执行流程（每次任务固定）

1. 读取上下文并输出“边界理解摘要”。
2. 定义本次目标、非目标、验证命令。
3. 先写/补测试（TDD），再实现最小改动。
4. 运行门禁并修复失败项。
5. 更新里程碑或 ADR。

## 输出格式要求

1. 先给“结果摘要”，再给“改动清单”，最后给“验证结果”。
2. 文件引用必须给到明确路径。
3. 若存在风险或未完成项，必须显式说明。

## 失败处理

1. 任一门禁失败，禁止宣告完成。
2. 不能在本轮修复时，必须给出可执行回滚方案与后续计划。
3. 禁止静默跳过测试或守卫命令。

## 变更范围控制

1. 一次任务只处理一个主目标。
2. 无关代码不混改，防止隐性回归。
3. 若发现系统性问题，先沉淀 ADR，再开新任务处理。
