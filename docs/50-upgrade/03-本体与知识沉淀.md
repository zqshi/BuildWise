# 03 本体与知识沉淀

## 1. 本体的双层结构

### 1.1 技术本体

由服务层自动构建和更新，不要求用户逐项确认。

包括：

1. 页面
2. 组件
3. API
4. 数据实体
5. 代码路径
6. 测试对象

作用：

1. 影响分析
2. 变更边界
3. 测试回归
4. 发布评审

### 1.2 业务规则本体

由用户通过自然语言持续输入，由 Agent 做映射。

包括：

1. 术语
2. 规则
3. 条件
4. 例外
5. 验收口径

作用：

1. 强化项目长期认知。
2. 和技术本体建立映射。
3. 为下一轮分析和发布提供上下文。

## 2. 项目知识库结构

建议最小结构：

存放在 `workspacePath/.buildwise/` 下：

1. `workspace.json`
2. `memory/project-summary.md`
3. `memory/ontology-business.md`
4. `memory/ontology-tech.md`
5. `memory/decisions.md`
6. `memory/release-history.md`
7. `memory/daily/<date>.md`
8. `shards/*.md`
9. `index/shards.json`

## 3. 写入时机

1. 项目 binding 建立或更新后。
2. 分析结果回写后。
3. 业务规则更新后。
4. 发布评审后。
5. 每日 0 点汇总任务。

## 4. 检索原则

1. 只检索当前项目。
2. 只召回命中分片。
3. 检索结果作为补充上下文注入 Agent。
4. 不把整个知识库直接塞进 system prompt。
