# 01 现状与目标

## 1. 当前断链

### 1.1 主窗口策略断链

问题：

1. 主窗口已经能做跨项目对话，但默认策略与项目执行的连接不稳定。
2. 用户能表达流程偏好，但很难被稳定继承到项目执行中。

目标：

1. 主窗口只负责默认策略。
2. 项目运行时继承默认策略，但不被固定流程锁死。

### 1.2 Skill 断链

问题：

1. skill pack、global custom skill、policy skillsPlan 的优先级和执行边界容易漂移。
2. 有些场景下 skill 只是展示信息，没有形成稳定注入。

目标：

1. registry 来源统一。
2. selection context 与执行注入一致。
3. Agent 只加载最小必要 skills。

### 1.3 本体与知识沉淀断链

问题：

1. 分析产物能生成，但没有稳定沉淀为项目长期知识。
2. 业务规则与技术实现的映射容易停留在当次对话。

目标：

1. 技术本体由服务层自动构建。
2. 业务规则通过自然语言持续补充并映射。
3. 所有沉淀回写到项目知识库。

### 1.4 OpenClaw 激活断链

问题：

1. 项目 binding 存在，但项目级 workspace 价值没有完全落地。
2. 项目知识更多以 prompt 拼接形式存在，而不是长期资产。

目标：

1. 每个项目一个独立 workspace。
2. session key、workspacePath、history 与项目边界一致。
3. BuildWise 负责知识资产化，OpenClaw 负责会话执行。

## 2. 目标架构

升级后的结构是：

1. 主窗口
   - 全局业务助手
   - 默认策略配置器
2. 项目 workspace
   - 项目级知识空间
   - 所有迭代共享
3. 迭代运行时
   - 项目空间内的执行上下文
4. OpenClaw 适配层
   - 非侵入式接入 OpenClaw 既有能力

## 3. 升级边界

本轮做：

1. 运行时稳定性治理。
2. 项目 workspace 和知识库落地。
3. skills 与策略链路收敛。
4. 文档、脚本、测试同步。

本轮不做：

1. 修改 OpenClaw 现有逻辑。
2. 替换 OpenClaw。
3. 重做主交互流程。
4. 新增与投产无关的新能力。
