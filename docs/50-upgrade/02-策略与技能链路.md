# 02 策略与技能链路

## 1. 主窗口策略定位

主窗口不是项目执行引擎，而是默认策略配置器。

它负责：

1. 接收用户用自然语言表达的流程偏好。
2. 将结果沉淀成默认策略和 skillsPlan。
3. 支持恢复默认配置。

它不负责：

1. 定义固定编排脚本。
2. 替代项目 workspace。

## 2. 默认策略如何生效

推荐链路：

1. 用户在主窗口调整流程偏好。
2. 系统将其解析为策略增量。
3. 策略增量回写到全局默认策略状态。
4. 项目执行时读取默认策略作为基线。
5. Agent 在基线约束下动态选择 skills。

## 3. Skills 体系收敛

现有可复用来源：

1. 文件型 skill pack。
2. 全局自定义 skill。
3. policy skillsPlan。

收敛要求：

1. registry 是唯一可见技能清单。
2. selection context 输出必须能被执行路径复用。
3. 仅向 Agent 注入当前阶段最小必要 skills。

## 4. 为什么不能写死流程

原因：

1. 用户可以在主窗口用自然语言调整流程。
2. 每个项目和迭代的风险点不同。
3. BuildWise 需要保留业务助理式对话弹性。

因此：

1. 默认策略是基线。
2. Agent 仍是运行时决策主体。
3. skills 是可选能力包，不是固定流水线。
