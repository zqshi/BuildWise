# 技术架构设计（执行版）

## 架构原则

- 采用 DDD 分层：`domain -> application -> infrastructure -> interfaces`。
- 入口层只做依赖装配，不承载业务规则。
- 前端按 `domain/infrastructure/shared/presentation` 分层组织。

## 后端上下文

- 当前核心域：`workspace`（项目、迭代、消息、评估、快照）。
- 领域层定义类型与仓储接口。
- 应用层编排用例流程（创建迭代、评估重算、快照恢复）。
- 基础设施层负责 JSON 持久化与外部适配。
- 接口层负责 HTTP 路由与请求响应模型。

## 前端上下文

- 领域类型统一放入 `src/domain`。
- HTTP 客户端与网关逻辑统一放入 `src/infrastructure`。
- 通用工具放入 `src/shared`。
- 容器组件负责编排，不重复定义领域模型。

## 扩展策略

- 新增业务能力时先落领域类型与用例，再暴露接口。
- 自动生成接口需隔离在专用路由模块，避免污染核心域路由。
- 所有模块必须满足边界守卫与行数阈值。
