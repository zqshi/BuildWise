# BuildWise 系统性治理升级设计

## 1. 设计结论

本轮治理只做技术层升级，不改产品主业务链路，不重做 UI，不新增主航道能力，不修改 OpenClaw 既有逻辑和运行机制。

落地原则如下：

1. BuildWise 继续使用 OpenClaw 现有 `agent + session + workspace + skills + history` 机制。
2. 不侵入 OpenClaw 内核，只在 BuildWise 侧做适配、绑定、知识组织和上下文注入。
3. 每个项目是一个独立 workspace。
4. 所有迭代都在所属项目 workspace 内持续沉淀知识，不为每个迭代新建 workspace。
5. 全平台只保留一个默认 OpenClaw Agent，不因新增项目而复制 Agent。
6. 主窗口保存默认策略与流程基线，但不把流程硬编码到 Agent 中。

## 2. 项目本质

BuildWise 不是通用聊天工具，也不是固定流程引擎，而是面向软件交付的项目级知识操作系统。

它的核心价值是把这些内容收敛到同一个项目知识边界中：

1. 多模态需求输入。
2. 业务规则与术语。
3. 页面、API、实体、代码路径等技术本体。
4. 交付物、测试、发布结论和历史决策。
5. 后续迭代对已有项目知识的继承、修正与召回。

因此，项目才是长期知识容器，迭代只是项目知识容器中的连续版本推进。

## 3. 当前实现可复用的 OpenClaw 机制

现有实现已经具备可复用的基础，不需要改 OpenClaw 本身：

1. `OpenClawGatewayClient`
   - 支持 `agentId`
   - 支持 `X-OpenClaw-Session-Key`
   - 已提供全局、项目、项目+迭代三种 session key 推导函数
2. `OpenClawAgentRunner`
   - `runWithHistory()` 已基于 `conversationId / projectId` 生成稳定 session key
   - `run()` 已支持按 `projectId + iterationId` 推导迭代级 session key
3. `ProjectWorkspaceBindingRecord`
   - 已支持 `projectId / openclawProfile / agentId / workspacePath / runtimeMode`
4. skills 体系
   - 已有 registry
   - 已有 selection context
   - 已有 policy skillsPlan 过滤与注入
5. 全局助手
   - 已有主窗口对话
   - 已有策略回写能力

这意味着本轮应当做的是“绑定规则、知识沉淀与注入逻辑收敛”，不是再造编排器。

## 4. 升级目标

### 4.1 项目隔离

1. 每个项目必须绑定独立 workspacePath。
2. 每个项目必须拥有稳定的项目级 session key。
3. 项目间 history 和知识上下文不得混用。

### 4.2 知识持续沉淀

1. 项目知识需要持续存储，而不是只在当前 prompt 中临时拼接。
2. 同一项目的全部迭代需要持续回写到同一个项目知识空间。
3. 需要支持分片、索引、按需检索和每日汇总。

### 4.3 动态执行

1. 主窗口自然语言配置只形成默认策略，不形成硬编码流程。
2. 项目执行时由 Agent 在默认策略约束下动态选择 skills。
3. 用户可通过自然语言恢复到默认策略。

### 4.4 生产可用

1. 修复健康检查、启动探针、鉴权、配置样例等运行时问题。
2. 让构建、类型、测试、门禁、文档一致。
3. 清理超长、失真、重复资产。

## 5. 升级后的运行模型

### 5.1 全局主窗口

主窗口是全局业务助手，不是项目知识空间。

职责：

1. 做跨项目思考和业务分析。
2. 保存默认流程策略、默认技能计划和治理偏好。
3. 接收“恢复默认配置”这类全局指令。

边界：

1. 不承载项目知识沉淀。
2. 不替代项目 workspace。
3. 不把流程写死到 Agent prompt 中。

### 5.2 项目 workspace

每个项目一个 workspace，这是 BuildWise 与 OpenClaw 集成的核心边界。

职责：

1. 承载该项目全部历史知识。
2. 作为项目级对话与迭代级对话的共同知识根。
3. 持续沉淀业务规则本体与技术本体。

约束：

1. 项目创建时建立 binding，不额外创建新 Agent。
2. 项目进入时注入基础信息和按需检索结果，不执行完整 BOOTSTRAP。
3. workspace 生命周期跟随项目，不跟随单个迭代。

### 5.3 迭代上下文

迭代是项目 workspace 中的运行态上下文，而不是新的知识边界。

职责：

1. 承载本次迭代的材料、分析、边界、交付、测试和发布状态。
2. 将新增知识回写到项目 workspace。

约束：

1. 迭代可以拥有自己的 session key。
2. 但知识回写目标仍是项目 workspace。

## 6. session key 设计

为了不改 OpenClaw 机制，直接复用现有 session key 规则：

1. 主窗口对话：
   - `agent:<agentId>:global-<conversationId>`
2. 项目级对话：
   - `agent:<agentId>:project-<projectId>`
3. 迭代级执行：
   - `agent:<agentId>:project-<projectId>-iteration-<iterationId>`

设计判断：

1. 新建项目应视为新的项目级 session 命名空间。
2. 新建迭代不新增 workspace，只新增该项目下的迭代 session。
3. 项目级 session 用于长期对话与项目知识连续性。
4. 迭代级 session 用于当前版本工作记忆，不替代项目知识库存储。

## 7. workspace binding 设计

每个项目只需要一条稳定 binding：

1. `projectId`
2. `openclawProfile`
3. `agentId`
4. `workspacePath`
5. `runtimeMode`

BuildWise 侧的职责是：

1. 创建或更新 binding。
2. 确保 `workspacePath` 对应项目隔离目录。
3. 将项目基础信息、知识摘要、检索结果注入 OpenClaw 上下文。

这里不需要：

1. 修改 OpenClaw workspace 内部结构定义。
2. 在 OpenClaw 中新增专门的项目初始化协议。
3. 为每个项目创建单独 Agent。

## 8. 项目知识库设计

项目知识库是 BuildWise 自己维护的项目资产，不要求 OpenClaw 直接承担知识库职责。

建议结构：

存放在 `workspacePath/.buildwise/` 下：

1. `workspace.json`
2. `memory/project-summary.md`
3. `memory/ontology-business.md`
4. `memory/ontology-tech.md`
5. `memory/decisions.md`
6. `memory/release-history.md`
7. `memory/daily/<date>.md`
8. `shards/*.md`
9. `index/shards.json`

知识类型分为两层：

### 8.1 技术本体

由服务层自动构建和更新，用户不逐项确认。

包括：

1. 页面
2. 组件
3. API
4. 数据实体
5. 代码路径
6. 测试对象

### 8.2 业务规则本体

由用户通过自然语言持续补充，Agent 负责映射到已有功能和技术本体。

包括：

1. 术语
2. 规则
3. 条件
4. 例外
5. 验收口径
6. 风险边界

## 9. 知识写入与检索

### 9.1 写入

触发时机：

1. 创建或更新项目 workspace binding 后。
2. 分析完成后。
3. 业务规则更新后。
4. 发布评审和版本结论更新后。
5. 每日 0 点汇总任务。

### 9.2 检索

检索原则：

1. 先查当前项目 workspace。
2. 只按需召回命中分片。
3. 不将整个知识库无差别注入 prompt。

这样既能复用 OpenClaw 的会话记忆能力，也避免把知识沉淀误做成超长 system prompt。

## 10. 技能与动态流程

主窗口可以自然语言调整流程，但不应把流程写死在 Agent 中。

正确做法：

1. 将主窗口输出沉淀为默认策略。
2. 项目执行时读取默认策略。
3. skills 继续通过现有 registry + selection context + policy skillsPlan 注入。
4. Agent 根据用户消息、项目阶段、知识命中和风险信号动态选择最小必要 skills。

默认策略的作用是“约束与基线”，不是“固定编排脚本”。

## 11. 定时汇总

每日 0 点任务由 BuildWise 侧实现，不要求改 OpenClaw 内核。

任务职责：

1. 遍历活跃项目 binding。
2. 汇总当日项目知识变化。
3. 更新 memory 文档。
4. 重建或增量更新知识索引。

这属于 BuildWise 的项目知识维护任务，不属于 OpenClaw 编排核心。

## 12. 生产治理项

### 12.1 已纳入本轮修复

1. `/health` 与 `/ready` 语义拆分。
2. 启动不再阻塞外部 LLM 探针。
3. `AUTH_MODE=off` 的默认权限收敛到 `viewer`。
4. `.env.example` 与真实路由前缀同步。
5. `README` 与实际 Node 版本要求同步。
6. 新增项目 workspace 知识物化与检索能力。

### 12.2 本轮必须继续收口

1. prompt replay 快照同步。
2. 超长升级文档拆分与去冗余。
3. 核心验证链重新跑绿。

## 13. In Scope

1. 运行时治理。
2. 项目 workspace 绑定治理。
3. 项目级知识库、检索和每日汇总。
4. 文档、接口、测试、脚本同步。
5. 冗余资产清理。

## 14. Out Of Scope

1. 修改 OpenClaw 现有逻辑和机制。
2. 替换 OpenClaw。
3. 大规模 UI 重做。
4. 变更产品主业务流程。
5. 新增与投产无关的新产品能力。
