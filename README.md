# BuildWise

> 业务人员直接推进软件交付的 AI 工作台。

BuildWise 让产品经理和业务负责人通过**对话和上传文档**的方式完成需求分析、变更评估、交付物生成和发布决策——不需要写代码，不需要等排期。

---

## 30 秒了解 BuildWise

**你的团队是不是这样？**

产品经理写完 PRD，研发说看不懂；需求改了一个字段，不知道影响了哪些页面和接口；上线前问"能发吗"，没人敢拍板；新人入职，问"当初为什么这么做"，没人记得。

**BuildWise 解决的就是这些问题。**

你上传需求文档（Word、PDF、截图、原型），AI 自动告诉你：

- 这次改动**影响了哪些业务流程和功能模块**
- 哪些地方**AI 理解不了、需要你确认**
- 自动生成**PRD、设计规范、测试用例、代码和发布评审**
- 能不能发布：**go / caution / block** 三档决策，附阻塞项和回滚方案

全程有 AI 教练在聊天窗口里引导你，像跟一个懂技术的项目经理对话。

## 核心能力

### 上传即分析

拖入需求文档，AI 在后台完成深度分析。你看到的不是一堆技术术语，而是：
- 高优先级发现（P0/P1/P2 排序）
- 需求到功能模块到代码的完整追溯链
- 与上个版本的变更对比
- 领域术语表（统一团队语言）

### 对话式工作台

不是填表单，是聊天。AI 教练全程伴随：
- 需求不清楚？教练主动提问帮你理清
- 想改原型？在预览界面点选元素，用中文描述修改
- 不确定影响范围？教练基于项目知识库给出评估

### 变更围栏 + 发布门禁

每次迭代强制经过：
- **边界声明**——明确做什么、不做什么
- **测试矩阵**——自动生成用例，逐条确认
- **发布评审**——基于证据的 go/caution/block 决策

### 项目越做越聪明

每次迭代自动沉淀到项目知识库：
- 业务术语（含别名和关联关系）
- 稳定规则（含来源和理由）
- 决策日志（当初为什么这么做）
- 已知风险（缓解措施和触发条件）

下次做需求分析时，AI 会利用这些积累给出更精准的判断。

## 一个迭代的完整流程

```
① 创建项目，配置代码仓库
② 创建迭代，设定目标和范围
③ 上传需求材料（拖拽即可）
④ 等 AI 分析完成（后台异步，有进度条）
⑤ 查看分析报告，回答澄清问题
⑥ 声明变更边界
⑦ AI 自动生成交付物（PRD、设计、代码、测试、原型）
⑧ 逐个确认或修改交付物
⑨ 执行测试矩阵
⑩ 发布评审 → 代码发布 → 知识自动回写
```

## 快速体验

**环境要求：** Node.js >= 22, npm >= 10

```bash
# 安装依赖
cd v2 && npm run install:all

# 启动前后端
npm run dev:stack:start
```

打开浏览器：
- 官网：`http://localhost:5173/#/`
- 工作台：`http://localhost:5173/#/dashboard`
- 后端：`http://127.0.0.1:5055`

**配置 AI 能力（二选一）：**

```bash
# 方式一：直接对接 LLM API
LLM_PROVIDER=anthropic LLM_API_BASE=https://your-api.com LLM_API_KEY=sk-xxx

# 方式二：通过 OpenClaw Agent（推荐，支持对话记忆和技能编排）
LLM_PROVIDER=openclaw OPENCLAW_GATEWAY_URL=http://127.0.0.1:18789
```

停止服务：

```bash
npm run dev:stack:stop
```

## 技术栈

- **前端**：React + TypeScript + Vite
- **后端**：Fastify + TypeScript
- **AI**：OpenClaw Agent（统一 Gateway），支持 15 个专业技能的自动编排
- **存储**：JSON 文件 / SQLite（可切换）

## 仓库结构

```

v2/backend/         # 后端服务、API 路由、领域模型

v2/backend/openclaw/# OpenClaw 运行时配置和 persona
docs/               # 产品、架构、治理文档
```
